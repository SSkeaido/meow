# CitationGuard 作品集案例说明

## 项目背景

论文经过翻译、润色和多轮修改后，原始引用经常无法完整支撑最终表述。传统做法主要依赖人工逐条回看文献，成本高、容易遗漏，也很难快速定位“表述比证据更强”的情况。

我实现了 CitationGuard，一套面向论文写作者的引用准确性审查平台。它把 PDF 解析、证据检索、主张抽取、引用判断和高风险复核串成可解释、可追溯的工程流程。

## 核心流程

```text
上传参考文献
→ PDF解析与分段
→ 文献去重和向量化
→ 相关证据检索
→ 提取论文主张
→ 判断引用支持程度
→ 高风险结果复核
→ 输出证据、风险等级和修改建议
```

## 关键工程决策

### 不把整篇 PDF 发送给大模型

先使用 PyMuPDF 提取文本，再切成带页码的片段，通过向量检索和重排筛选候选证据。模型只接收当前主张和必要证据，降低成本，也减少未发表论文内容的暴露范围。

### 固定工作流优先于全自动 Agent

引用审查需要稳定、可重复和可审计。固定流程负责默认检查；Agent只作为高风险结果的深度复核工具，并设置最大步骤、模型调用次数和可访问范围。

### 访问密钥与工作区绑定

内测阶段使用哈希存储的一周访问密钥。项目、参考文献、论文内容和审计历史都绑定到密钥对应工作区，兼顾内测体验和数据隔离。

### 小服务器上的批量处理

一次选择100篇 PDF 不等于同时解析100篇。前端限制单批数量，后端将任务排队并设置受控并发；普通文本 PDF 和 OCR 任务使用不同并发上限，避免内存和 CPU 被瞬间耗尽。

## 当前成果

- React + TypeScript 前端工作台。
- FastAPI 后端和结构化数据模型。
- PyMuPDF 解析、BGE-M3检索、BGE重排和SiliconFlow模型路由。
- Qwen主张提取与引用判断，DeepSeek高风险复核。
- 7天访问密钥、历史内容查看和Markdown/CSV导出。
- 本地启发式模式，支持无云模型Key时的开发与测试。

## 诚实的限制

当前版本定位为小规模内测原型：模型结果是辅助审查意见，不等价于学术事实证明；大规模并发仍需要生产级任务队列、对象存储、监控和备份；Agent深度复核属于下一阶段功能。

## 下一步路线

1. 完善异步解析队列和任务进度。
2. 增加高风险结果的Agent深度复核按钮。
3. 对公开文献增加 DOI、Crossref/OpenAlex 元数据补全。
4. 增加用户主动删除和数据生命周期管理。
5. 通过标注数据评估主张提取和引用判断准确率。
