# CiteXS 竞品调研笔记

调研时间：2026-07-20

调研对象：https://www.citexs.com/

## 一句话判断

CiteXS 不是单纯的论文关系图工具，而是一个面向科研写作全流程的工具集合：文献检索、知识图谱、研究热点、研究趋势、研究空白、文献调研、单篇追溯、文献计量、写作润色、翻译、期刊投稿辅助等能力都被产品化为独立入口。

对我们要做的 "Connected Papers 改良版" 来说，CiteXS 更像是一个功能边界很宽的参考对象。它的启发不在于复刻全部功能，而在于把"论文发现"继续往"选题判断、证据组织、综述生成、写作交付"推进。

## 可见功能入口

根据官网公开页面与前端路由，CiteXS 至少包含这些能力：

| 模块 | 可见入口 | 产品含义 |
|---|---|---|
| 文献检索 | PubMed 文献库、中文文献库、英文综合数据库 | 多来源文献入口，不只依赖单一数据库 |
| 知识图谱 | 研究热点分析、知识图谱、研究脉络、热度走势 | 把主题相关文献做成可视化分析 |
| 相关文献 | 相关文献、单篇文献追溯 | 类似 Connected Papers 的单篇论文扩展和追溯 |
| 研究空白 | 寻找主题研究空白点、课题空白点挖掘 | 从文献集合中辅助判断选题机会 |
| 领域调研 | 领域文献调研、文献精读报告 | 从发现文献推进到综述/调研报告 |
| 文献计量 | 综合文献大数据分析、PubMed 计量分析、LDA 分析 | 面向 bibliometric analysis 的图表和统计 |
| 写作辅助 | 结构化写作、学术智能写作、文献语料库 | 从资料整理推进到论文写作 |
| 语言处理 | 在线翻译、PDF 翻译、英文润色、全文润色 | 面向论文读写场景的刚需工具 |
| 投稿辅助 | SCI 期刊查询、智能选刊、期刊预警、投稿信、催稿信 | 从文献研究延伸到发表环节 |

## 对我们产品的启发

1. Connected Papers 的核心是"从一篇论文找到相关论文"，但用户真正想完成的是"知道这个方向怎么发展、哪些论文必须读、研究空白在哪里、综述怎么写"。

2. CiteXS 的产品路线说明，论文关系图可以只是入口，后面可以接：

```text
论文发现 -> 主题聚类 -> 研究脉络 -> 研究空白 -> 文献矩阵 -> 综述草稿 -> 引用溯源 -> 导出
```

3. 我们不应该第一版就做成 CiteXS 那样的大而全工具箱。更适合的切入点是：

```text
输入主题或种子论文
生成论文关系图
自动分组主题簇
生成每个主题簇的代表论文和关键观点
输出文献矩阵
生成带引用的综述大纲和初稿
```

4. CiteXS 的多个功能明显面向生物医学和科研写作群体，这说明垂直领域有价值。但我们的第一版可以做成通用学术场景，后续再扩展医学、生物、社科等垂直模板。

## 我们可以做的差异化

| 方向 | CiteXS 观察 | 我们的改良机会 |
|---|---|---|
| 图谱体验 | 有知识图谱和单篇追溯入口 | 做更清晰的论文关系网络，支持引用关系、语义相似、方法相似、数据集相似分层切换 |
| 综述生成 | 有领域调研和精读报告 | 强化"每一句话可追溯到论文证据"，避免 AI 综述像作文 |
| 用户流程 | 功能入口很多 | 做成任务流：选题 -> 检索 -> 筛选 -> 图谱 -> 矩阵 -> 综述 |
| 研究空白 | 有研究空白挖掘 | 用"证据不足/争议点/方法局限/数据缺口"四类结构化输出 |
| 数据来源 | 有 PubMed、中文、英文综合库入口 | 优先接 OpenAlex、Semantic Scholar、Crossref、PubMed、arXiv 等 API，降低数据授权风险 |
| 商业化 | 功能多，可能会员制 | 第一版聚焦高频任务，后续按导出、高级图谱、团队库、深度综述收费 |

## MVP 建议

第一版不要做"科研工具大全"，只做一条最核心的闭环：

```text
研究主题/种子论文输入
-> 文献检索
-> 论文关系图
-> AI 主题聚类
-> 用户选择要纳入综述的论文
-> 文献矩阵
-> 带引用综述大纲
-> 综述初稿导出
```

优先功能：

1. 主题检索：接 OpenAlex / Semantic Scholar / PubMed。
2. 论文关系图：节点是论文，边可以先用引用关系和语义相似度。
3. 主题簇：自动将论文分成若干研究方向。
4. 论文卡片：摘要、贡献、方法、结论、局限、引用数、年份。
5. 文献矩阵：按论文横向对比研究问题、方法、数据、结论、局限。
6. 综述大纲：按主题簇生成章节结构。
7. 引用溯源：每段观点绑定来源论文。

暂缓功能：

1. 期刊投稿辅助。
2. PDF 全文翻译。
3. 论文润色。
4. 基金申请书。
5. 复杂文献计量高级分析。

这些功能都很有价值，但会拉长第一版周期，也会稀释"Connected Papers 改良版"的核心定位。

## 风险与注意点

1. 不要直接复刻 CiteXS 的 UI、文案、功能命名和业务流程，应只作为竞品观察。
2. 文献元数据要优先使用授权清晰的 API 和开放数据源。
3. 论文全文解析需要注意版权，产品上应支持用户上传自己有权使用的 PDF。
4. 生成综述必须做引用溯源和证据校验，否则容易变成不可控的 AI 写作工具。
5. 论文关系图的算法要透明，例如区分"引用关系"和"语义相似关系"，不要让用户误以为图上的边都代表真实引用。

## 后续待调研

1. Connected Papers 的图谱交互细节与收费边界。
2. ResearchRabbit、Litmaps、Inciteful、OpenAlex Explorer 的差异点。
3. 可商用的数据源 API：OpenAlex、Semantic Scholar、Crossref、PubMed、arXiv。
4. 论文图谱算法路线：引用网络、共被引、文献耦合、语义 embedding、混合排序。
5. 综述生成的证据链设计：原文 chunk、论文卡片、矩阵字段、段落引用之间如何关联。
