About / Project Owner

何珊 / Luna：把用户调研、业务流程和 AI 能力连起来

我是市场营销本科、企业管理硕士背景的 AI 产品 / FDE 方向候选人。这个项目不是从“想做一个 AI 工具”开始，而是从装修用户调研中反复出现的签约焦虑开始：费用不透明、承诺不落纸、责任边界不清、后续维权成本高。

业务理解

从真实痛点收敛 MVP

从 B 端销售辅助转向 C 端业主签约前审查，聚焦报价、合同、承诺和追问清单，而不是做大而全的装修平台。

设计“结构化知识卡 + 两轮检索 + LLM 生成”的流程，让每个风险卡片绑定依据，避免无依据的确定性结论。

FDE 能力

把原型落成可演示系统

完成 PRD、RAG 知识库、Prompt 约束、Web 原型、桌面演示版和评测指标，展示从业务问题到工程原型的闭环。

01 / Problem Insight

从“装修公司销售工具”转向“业主风险审查工具”

初始方向是帮助装修公司销售解释报价，但用户调研后发现，真正更痛的一方是签约前的业主：他们面对高金额、低频、强信息差的消费决策，很难判断报价和承诺是否可靠。

初始假设

B 端销售辅助

帮助销售生成报价说明、责任边界和销售话术，以提升成交率。

调研修正

C 端签约前审查

帮助业主看懂报价、合同和销售承诺，生成签约前追问清单。

客户真正怕的不是贵

而是签约前说得很好，签约后漏项、增项、延期、返工和责任推诿。

AI 不做法律裁判

系统只把材料中的不确定点转成风险提示、追问问题和人工复核事项。

作品集价值在于重定位

项目展示的不是“做了页面”，而是从业务假设中收敛出更真实的用户切口。

02 / Product Solution

V1 MVP 只聚焦签约前风险审查

为避免产品变成泛装修管理平台，V1 收敛在业主签约前最需要的 5 个能力：报价审查、合同条款审查、销售承诺核对、追问清单和人工复核提示。

01

资料输入

粘贴报价单、合同文本、销售沟通记录。

02

AI 审查

解析触发词，匹配审查依据，生成风险。

03

风险总览

先看结论、风险等级和重点风险卡片。

04

结构化报告

输出风险明细、漏项、责任边界和追问清单。

报价单审查

识别报价不清、按实结算、套餐外另计、水电不封顶等费用风险。

合同条款审查

检查付款节点、工期、材料替换、验收、售后和变更规则是否写清。

销售承诺核对

把“无增项、全程管理、赠送项目”等口头承诺转成书面确认问题。

人工复核提示

没有依据或涉及责任认定的内容，不生成确定性结论，进入人工复核。

03 / RAG + LLM Architecture

先找依据，再生成风险解释

系统不是让 LLM 直接“凭感觉审合同”，而是先通过结构化知识卡和本地相似度检索召回证据，再把用户材料和证据交给 LLM 生成结构化报告。

知识库分层

A 合同硬知识与验收标准，B 消费提示，C 典型案例，D 项目经验规则。

证据绑定

风险卡片必须绑定审查依据；没有依据的内容只能进入人工复核。

兜底机制

LLM 不可用时仍可用本地规则和知识卡生成基础报告，保证演示不中断。

05 / Evaluation System

从模型能力和业务实现双层评测

评测不只看回答是否流畅，而要验证“准不准、有无依据、用户能不能用”。

模型能力评测

  • 风险识别召回率
  • 误报率与漏报率
  • Top-K 证据相关性
  • evidenceId 覆盖率
  • 边界违规率

业务实现评测

  • 用户是否看懂报告
  • 追问清单是否可直接使用
  • 是否帮助暂缓或补充签约确认
  • 是否理解 AI 不替代法律/监理
  • 是否愿意进入人工复核
